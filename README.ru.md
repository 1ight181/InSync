# InSync

InSync — это инструмент синхронизации файлов в локальной сети, построенный вокруг модели трёх снимков: base, local и remote. Проект использует three-way merge для сравнения состояний, обнаружения конфликтов и применения изменений в предсказуемом порядке.

InSync предназначен для синхронизации файловых деревьев по сети в формате REPL. Узлы обнаруживаются через mDNS, обмен данными выполняется через gRPC, а соединение защищается mutual authentication на основе сертификатов.

---

## Возможности

- Трёхсторонняя синхронизация по схеме base / local / remote  
- Двусторонний sync  
- Обнаружение конфликтов при расхождении состояний  
- Детерминированное слияние изменений  
- Контрактная модель работы с путями и структурой дерева  
- Строгое нормализованное представление путей  
- Расширяемая архитектура команд и транспортного слоя  

---

## Архитектура

InSync построен вокруг концепции трёх снимков:

- **Base** — предыдущее синхронизированное состояние  
- **Local** — текущее состояние на локальном узле  
- **Remote** — текущее состояние на удалённом узле  

### Слои системы

**REPL-слой**  
Пользователь работает с приложением через интерактивную консоль и вводит команды по мере необходимости.

**Transport layer**  
Для обмена данными между узлами используется gRPC.

**Discovery layer**  
Для поиска узлов в локальной сети используется mDNS.

**Security layer**  
Соединение защищено mutual authentication: и клиент, и сервер предъявляют сертификаты.

**Hashing layer**  
Для вычисления хэшей используется BLAKE3.

### Особенности реализации

Контрактная модель позволяет быстро проходить по дереву в лексикографическом порядке и пропускать неизменённые поддеревья. Это снижает объём лишней работы и делает поведение системы более предсказуемым.

---

## Основные идеи

**Контракт превыше всего**  
Все пути должны быть нормализованы, а структура дерева — заранее определённой и проверяемой. Это упрощает обработку состояния и делает алгоритм синхронизации детерминированным.

**Безопасность соединения**  
Для взаимодействия узлов используется взаимная аутентификация по сертификатам. Это снижает риск подключения к неподтверждённому узлу.

**Детерминизм**  
Одинаковые входные данные должны приводить к одинаковому результату.

**Простота и лёгкость важнее универсальности**  
Некоторые сложные случаи намеренно не поддерживаются, включая симлинки и виртуальные файловые системы.

Для сборки и запуска проекта потребуются:

- Go  
- поддержка сертификатов для клиентского и серверного узлов  
- возможность запуска узлов в локальной сети

## Установка

```bash
git clone https://github.com/1ight181/InSync
cd InSync
go build -o insync ./cmd/insync
```

Если используется Windows-сценарий генерации сертификатов, его удобно запускать отдельно из каталога `certsgen`.

---

## Подготовка сертификатов

Перед запуском узлов необходимо подготовить CA-сертификат, а затем выпустить и подписать сертификаты для сервера и клиента.

Если в репозитории используются готовые batch-скрипты из `certsgen`, сначала создаётся CA, затем на его основе создаются сертификаты узлов.

Порядок действий:

1. Сгенерировать CA-сертификат
2. Сгенерировать серверный сертификат
3. Сгенерировать клиентский сертификат
4. Убедиться, что оба узла используют согласованный набор сертификатов

## Использование

### 1. Запуск REPL

```
insync
```

После запуска пользователь попадает в интерактивный режим и может выполнять команды последовательно.

---

### 2. Поиск узлов

```
insync> nodes
```

Команда выводит список доступных узлов в локальной сети.

---

### 3. Подключение к узлу

```
insync> connect nodeNameExample
```

После подключения становится доступен обмен состояниями и управление синхронизацией.

---

### 4. Добавление root

На каждом узле создаётся root, содержимое которого будет синхронизироваться.

На локальной стороне:

```
insync> add-root exampleRoot "/path/to/example-root"
```

На удалённой стороне:

```
insync> add-root exampleRoot "/path/to/remote-root"
```

---

### 5. Инициализация base snapshot

После добавления root можно инициализировать базовое состояние:

```
insync> init exampleRoot
```

---

### 6. Проверка изменений без применения

```
insync> dry-run exampleRoot
```

Команда показывает список предполагаемых изменений и возможных конфликтов, не внося фактических правок.

---

### 7. Применение синхронизации

```
insync> sync exampleRoot
```

Команда последовательно применяет все необходимые изменения. Если обнаружены конфликты, они выводятся пользователю для принятия решения.

---

### 8. Назначение алиаса узлу

```
insync> set-alias nodeNameExample aliasExample
```

Алиас отображается рядом с именем узла и упрощает работу в REPL.

---

## Команды REPL

- `nodes` — показать доступные узлы
- `connect <nodeName>` — подключиться к узлу
- `current-node` — показывает текущий подключенный узел
- `add-root <rootName> <path>` — добавить корневой каталог для синхронизации
-  `remove-root  <rootName>` — удаляет корневой каталог для синхронизации
- `init <rootName>` — создать base snapshot для выбранного узла
- `dry-run <rootName>` — показать план синхронизации без применения
- `sync <rootName>` — применить изменения
- `set-alias <nodeName> <alias>` — назначить алиас узлу
- `remove-alias <alias>` — удалить назначенный алиас
